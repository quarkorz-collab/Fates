# Fates v1.0.8 — 有预算上限的终局补全

## 更新内容

- 修复部分一元中间表达式在深层组合前被裁掉而导致的漏解。原先不启用 `cos` 的完整参数，现在可找到 `tan(ln(2))+sin(asin(1)-sin(1))`，成本15，与 `cos(sin(1))+tan(ln(2))` 等价。
- 新增 `--completion-mode auto|full|off`，默认 `auto`。采用携带真实成本与约束节点的统一伙伴索引，减少重复查询、排序和临时节点构造。
- 新增 `--completion-budget N`：0自动分配，非零值仅用于auto。所有deep轮次共享额外工作额度；不会减少用户的pairs或inverse预算，也不改变 `--no-stop` 的主搜索行为。
- nearest模式已有满足阈值且传播误差估计足够小的命中后，auto仅继续尝试可能降低成本的额外补全。full保留广泛补全及根逆分支公平预算分配；off仅关闭额外补全。
- 保留辅助节点的累计误差及约束状态，固定深层任务分块，使相同配置的结果和计数不依赖线程数。
- 网页端增加补全策略和预算控件，支持命令导入、导出与参数校验；Android共享相同界面，版本号1.0.8 / versionCode8。

原命令无需增加新选项，默认即为auto；需要完整增强时追加 `--completion-mode full`。有界搜索仍不保证枚举所有表达式，full与auto不保证返回相同候选列表。

## 质量与性能验证

- 60组既有配置及12个预先固定的保留目标：auto保住4个已知漏解修复，相对full未见显著最佳误差或最低命中成本退化。显著误差变化沿用“较差归一化误差超过1e-14且相差至少2倍”的判据。
- 保留集另外验证了3个命中目标，其中包括 `sin(exp(1/3))*ln(5)`、`sqrt(2+sin(3))+atan(2/3)`。本地上一版完整增强构建也能命中它们；这是新增测试证据，不是auto独有的新能力。
- 返回表达式经过80位离线重算，156个最佳结果进一步经过160位复核。正式引擎仍使用double，离线复核位数不代表引擎数值精度。
- 8组增强配置、每组各3轮交错测试：auto较本地上一版完整增强构建节省约7.8%耗时，但较修复前基线仍增加11.4%，未达到额外开销3%以内的目标。原始命令未证明稳定整体提速；峰值内存基本不变。
- 9组普通配置各3轮对照：最佳误差相同，总体耗时和内存基本不变，单项仍有波动。
- 本地最终Windows构建通过83项C++自测、90次策略/预算/约束/线程回归，以及原始完整参数1/4/16线程一致性检查；网页源码和独立打包版通过搜索、实时输出、错误处理和取消检查。

以上性能结果针对本地已验证的Windows AVX2 PGO构建与固定样本，不是所有机器、平台或输入上的性能保证；“上一版完整增强构建”是本地中间版本，并非GitHub上一公开版本的新功能承诺。

## 下载与构建来源

- `fates-windows-x64-pgo-avx2.zip`：本地已验证的MSVC x64、AVX2、balanced PGO构建，包含独立WebUI。需要支持AVX2的CPU。
- `fates-android-arm64-debug.apk`：本地已验证的ARM64 1.0.8 APK，沿用本地Debug签名；ZIP 16KB对齐与原生引擎LOAD段对齐检查通过。
- Windows portable、Linux portable、Linux AVX2 PGO/Web、macOS portable：从同一标签由GitHub Actions构建和测试。
- 每个下载文件附有SHA-256校验文件；Windows/Linux PGO训练使用 `release-balanced-v3`。所有包来自同一版本源码，但本地和CI工具链不同，不要求二进制逐字节相同。

### Android 安装注意

APK仅支持ARM64，使用Debug签名，不是商店发行签名包。本次沿用本地构建的签名，但它与此前GitHub Actions每次临时生成的Debug签名不同；从旧GitHub APK更新可能提示签名冲突。请先备份需要保留的数据，再决定是否卸载旧版后安装，卸载会删除应用本地数据。

未连接Android真机，未验证手机端启动、搜索、取消、耗时或峰值内存。原始大预算在Windows上峰值内存约2.5GB，不宜据此假定手机上也能正常运行。
